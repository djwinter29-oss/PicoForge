# SDIO CRC throughput optimization at 150 MHz

## Scope

Pico 2 / RP2350, system clock 150,000,000 Hz, 4-bit PIO SDIO 25,000,000 Hz. The HID benchmark asserts both runtime clocks before each run. No overclocking, formatting, CRC bypass, commit or push. Baseline is commit `1a28ec9` on `fix-sdcard`; results below use uncommitted protocol changes.

## Kept changes

- Fold four wire bytes per CRC update using slicing-by-4 tables.
- Store table entries in separate high/low 32-bit arrays for Cortex-M33 loads.
- Add a TX byte lane-map lookup, preserving arbitrary supported lane permutations.
- Preserve CRC verification, DMA bounds/alignment/barriers and error cleanup.
- Use memcpy-based, endian-aware word loads; add input-alignment and lane-table regressions.

CRC tables increase from 2 KiB to 8 KiB; TX lane-map storage adds 256 bytes. Lazy table initialization retains the existing serialized-caller assumption, documented in source.

## File-level measurements

Same card as baseline (7,969,177,600 bytes), existing FAT volume; no preallocation or benchmark timing changes. Each run creates a new temporary file, writes it, syncs/closes it, reads and verifies every byte, then deletes it and unmounts. Read timing includes full pattern verification; write timing includes sync/close. Units are decimal MB/s, calculated from bytes and elapsed milliseconds.

Baseline three 128 MiB runs: mean write 6.498770 MB/s, mean read 6.557123 MB/s.

Kept slicing-by-4 / split-table candidate:

- 32 MiB smoke: write 7.553902 MB/s, read 7.756457 MB/s, PASS.
- 128 MiB run 1: write 7.783445 MB/s, read 7.778934 MB/s, PASS.
- 128 MiB run 2: write 7.987249 MB/s, read 7.784348 MB/s, PASS.
- 128 MiB run 3: write 8.203015 MB/s, read 7.784348 MB/s, PASS.
- Mean: write 7.991236 MB/s (+22.97%), read 7.782543 MB/s (+18.69%).

All listed runs completed the full requested write/read byte counts with zero mismatches, zero reported errors, no remaining temporary file and no mounted volume. Write variation is visible; 8.203015 MB/s is a single-run maximum, not a sustained-rate guarantee. No long-duration endurance qualification was performed.

Raw JSON: local scratch files `picoforge-150mhz-slicing4-split-32m.json` and `picoforge-150mhz-slicing4-split-128m-{1,2,3}.json` under `/home/home/.hermes/cache/scratch/` (ephemeral).

## Rejected candidates

- Moving encode/decode to SRAM: 128 MiB read 7.277829 MB/s, below the preceding slicing-by-4 result around 7.555 MB/s. Removed; no claim about the exact contention cause.
- Slicing-by-8: compiled trial used twice the CRC table RAM without reducing loop instructions per byte on Cortex-M33. Removed before HIL; no measured throughput claimed.

## Remaining gap

The user's external 10.4/8.7 MB/s reference has not been independently matched to a specific card, direction, clock, preallocation setting or timing boundary. The target numbers were not reached. The kept improvement demonstrates that CRC/byte mapping CPU work was a material contributor, not the sole proven bottleneck. Distinguishing the remaining CPU, card, command-gap and filesystem costs requires direct phase profiling or a comparable benchmark, not removing integrity checks.
